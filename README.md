# R太郎と伝説の海鮮丼

Phaser 3 / TypeScript strict / Viteで作る、オリジナル生成ドット絵の見下ろしRPG。第1章「武蔵小杉のぬいぐるみ大騒動」を実装しています。

## 起動

Node.js 20.19以降（推奨22）とnpmが必要です。

```sh
npm install
npm run dev
```

表示されたURL（通常 http://localhost:5173 ）をPCのChromeまたはEdgeで開いてください。初回依存導入にはインターネット接続が必要です。ゲーム自体は外部API・外部サーバー不要です。

```sh
npm test
npm run build
npm run preview
```

## 操作

- 矢印 / WASD：移動、コマンド選択
- Z / Enter：会話、決定、次へ
- X / Escape：メニュー、キャンセル
- NPCに近づいて決定すると会話できます。道の左右端で隣のエリアに移動します。
- 戦闘では各メンバーが順に行動した後、敵が行動します。海鮮丼は対象を選択できます。気絶した仲間にも使用できます。
- 防御は被ダメージを軽減しMPを3回復。自宅のベッドでHP/MPを全回復できます。
- メニューの海鮮丼は1個で全員のHPを80回復します。伝説の海鮮丼は消費されません。

## 第1章の進め方

ママと会話 → 東の公園でマーモット加入 → 東の商店街でふぐ加入 → 東の駅前でヴァニラ・アイス加入 → 駅前広場のモフモフキングを倒す → 羽田空港行きの切符とクリア画面。

見える敵との接触で戦闘になります。敗北時は自宅へ戻り全回復、海鮮丼を最低3個まで補充します。勝利・加入時に自動保存し、メニューから手動保存できます。同じブラウザ・同じURLのLocalStorageを使用します。ブラウザのデータ削除で保存も消えます。

## 構成

- `src/scenes/`：タイトル、フィールド、戦闘、クリア
- `src/game/battle.ts`：Phaser非依存の戦闘計算
- `src/game/data.ts`：キャラクター、魔法、敵、マップ定義
- `src/game/state.ts`：進行、保存データ検証、LocalStorage
- `src/game/art.ts`：生成テクスチャ。同じキーでPNGをロードすれば差し替え可能

論理解像度640×360、標準1280×720、16:9の可変表示。補間は無効です。既存作品の画像・音楽は使用していません。

## 公開前の表記・プライバシー確認

タイトルと主人公の表示名は「R太郎と伝説の海鮮丼」「R太郎」です。会話・フィールド・戦闘・パーティーメニュー・クリア画面はこの表記を使用します。セーブは表示名を保存せず、読み込み時にキャラクター定義から表示名を取得するため、既存データも新しい表示名になります。

既存セーブとの互換性を維持するため、内部のキャラクターID・テクスチャキー・LocalStorageキーは変更していません。これらは画面上の名前には使用しません。

現行の公開用ソースとアセットを点検し、顔写真、実際の自宅住所、メールアドレス、電話番号は見つかりませんでした。武蔵小杉とノルウェーは物語の舞台設定として残しています。生成ドット絵以外の画像ファイルはありません。診断ログは開発環境の情報を含むため公開対象に含めず、GitHub Pagesにはビルド結果の`dist/`のみを配信してください。この点検はGit履歴や外部サービス上のリポジトリ設定・プロフィールを含みません。

## GitHub Actionsによる自動公開

`.github/workflows/deploy.yml` は `main` への push または Actions の手動実行で、依存導入・テスト・ビルドを実行し、成功した場合のみ GitHub Pages にデプロイします。GitHub の Settings → Pages → Source を **GitHub Actions** にしてください。無料アカウントの非公開リポジトリでは Pages 公開が利用できない場合があります。公開前に個人情報を点検してください。

注意: このバージョンはキーボード操作が前提で、スマートフォンのタッチ操作は未実装です。

## PNGグラフィックの統合

4人の32×48・4方向×3フレームPNGを独立したアセットとして使用します。仲間になるとフィールドの隊列に加わり、主人公の経路を歩きます。表示倍率は全員1倍（ゲーム画面全体は標準2倍）です。32×32タイルは地面・道路・建物・店先・木・看板の各レイヤーで描画します。画像が読み込めない場合は仮素材に切り替えます。詳細は[アセット仕様](docs/ASSETS.md)を参照してください。

ブラウザ検証は、別ターミナルで`npm run dev`を起動してから`npm run test:browser`を実行します。Chromiumの場所は`CHROMIUM_PATH`、接続先は`GAME_URL`で指定できます。
