# オリジナル16bit風アセット仕様

既存ゲーム・アニメからの画像コピー、トレース、素材抽出はしていません。同梱PNGはこのプロジェクト用に作成したオリジナルです。`scripts/generate_assets.py`が制作元で、Python 3 + Pillowを用意すると再生成できます。プレイ・npmビルドにPythonは不要です。

## 配置

| 対象 | 公開パス | 実行時キー |
| --- | --- | --- |
| R太郎 | `public/assets/characters/rtaro.png` | `rintaro`（互換用） |
| マーモット | `public/assets/characters/marmot-plush.png` | `marmot` |
| グアムバード | `public/assets/characters/guam-bird.png` | `fugu` |
| シンガポール太郎 | `public/assets/characters/singapore-taro.png` | `vanilla` |
| 武蔵小杉タイルセット | `public/assets/tilesets/kosugi.png` | `kosugi-tiles` |

Viteの`BASE_URL`を使ってロードします。GitHub Pagesのサブディレクトリにも対応します。PNGはリポジトリに含めてください。ファイル名は小文字・完全一致です。

## キャラクター

- RGBA PNG、背景透過、96×192ピクセル。
- 1コマ32×48、横3コマ・縦4方向。余白・間隔は0。
- 行順は「下・左・右・上」。各行「左足・待機・右足」。
- フレーム番号は0〜11。初期表示は下向き待機の1。
- アニメーション順は各行の「1→0→1→2」、毎秒8コマ、ループ。
- ワールドの既存座標を維持するためフィールド原点は `(0.5, 2/3)`。画像左上から `(16,32)` が元の保存座標に対応し、足元はおおむねy=44。
- 主人公の物理ボディは16×12、オフセット(8,36)。以前の素材とワールド上の衝突位置は同じ。
- 透過領域を含むセルサイズを守ってください。表示補間はNEAREST。
- 共通のアニメーションは4人分をBootで登録。現在プレイヤーとして歩くのはR太郎で、加入前の仲間・タイトル・クリア画面は待機フレームを使用します。

## タイルセット

RGBA PNG、256×192、32×32ピクセル×横8列・縦6行。余白・間隔0。タイルIDは左上から0開始です。未使用枠も透過のまま残し、サイズを変えないでください。

| ID | 内容 |
| --- | --- |
| 0〜2 | 草地、草むら、花 |
| 3〜6 | 舗装、道路、上縁石、下縁石 |
| 7 | 水面 |
| 8〜15 | 壁、窓、扉、屋根、軒、ひさし、レンガ、看板 |
| 16〜21 | 64×96の木を2列×3行に分割（行順） |
| 22〜28 | 生垣、植木鉢、ベンチ、街灯、階段、池の縁、半透明の影 |
| 29〜47 | 将来拡張用の透過枠 |

定義は`src/graphics/spec.ts`。地形データは`mapLayout.ts`、描画は`mapRenderer.ts`で管理します。

## マップレイヤーと衝突

`ground`（地面）、`roads`（道路）、`shadows`（影）、`decorations`（小物）、`buildings-*`（建物）、`signs`（看板）、`foliage-*`（木）を独立したPhaser TilemapLayerとして生成します。木はそれぞれY座標で前後関係を決めます。建物ごとの表示位置は従来の座標を保持し、セル数は32ピクセル単位に丸めます。

この段階では衝突はタイルの属性から自動生成せず、既存の矩形を保持します。追加した鉢・看板などは装飾で、通路を新たに塞ぎません。タイルサイズに合わせた建物の衝突再設計やTiled JSONへの移行は次段階です。

## 読み込みとフォールバック

`Boot`がロード→寸法検証→不足素材の補完→アニメーション登録を行い、タイトルに進みます。単独のPNGが404、壊れている、寸法違いでも他の素材は利用します。キャラクターは同じ32×48・12フレームの仮シート、タイルは同じID配列の仮アトラスに置き換えます。フォールバックの画質は簡易です。

敵、一般NPC、ベッド、タイトルの木は従来のGraphics生成を残しています。PNG移行の段階では戦闘計算・加入順・ストーリー・LocalStorage形式を変更していません。Ver.2 Phase 1では戦闘と保存形式を更新しており、現在の仕様は[Phase 1仕様](PHASE1.md)を参照してください。今後、同じ方式で段階的にPNG化できます。

## 差し替え手順

1. 上記仕様のPNGを同じパスに置く。
2. `npm test` と `npm run build`。
3. 通常起動とPNG欠落時、4方向歩行、建物前後、各エリア遷移を確認。
4. 過去のセーブでロードできること、戦闘・加入イベントが進むことを確認。

PNGを含む通常配信には外部画像サーバーや外部APIは不要です。

## ブラウザ回帰チェック

別ターミナルで`npm run dev`を起動し、`CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`を実行できます。Chromiumのパスは環境に合わせて指定してください。PNG使用時と全PNG欠落時、4方向と待機、メニュー、既存v1形式セーブの読込、4エリア描画、4人での魔法・ボス戦・クリアを確認します。ゲーム本体にはテスト用グローバル変数を追加せず、テストブラウザ内でのみ起動コードを計測します。最初からのストーリー加入順の通しプレイを代替するものではありません。

## 既存GitHubプロジェクトへの統合時の調整

4人の表示倍率は`CHARACTER_SCALE = 1`に統一しました。論理解像度640×360を2倍表示した場合、1コマの表示領域は64×96になります。タイトル・フィールド・クリア画面で同じ倍率を使用します。

加入した仲間は`PartyView`がフィールド上で隊列表示します。移動履歴から30px間隔の追従先を求め、向きに応じて各自のスプライトシートをアニメーションします。停止・会話・メニューでは待機フレームになります。見た目だけの追従で、物理衝突や敵・NPCへの接触判定は主人公だけが担当します。追加の位置情報はセーブに保存しません。

商店街は既存タイルのひさしを店舗ごとに配置し、家や店舗へのアプローチ、駅前広場と入口の階段を追加しています。建物、道、木、看板、店先は独立したレイヤーです。

シンガポール太郎の内部ID・テクスチャキーは、既存セーブと素材参照の互換性のため `vanilla` を維持します。表示名はキャラクター定義から取得します。添付のぬいぐるみ写真は公開アセットに含めません。

グアムバードは、紺色の羽・白いお腹・青いくちばし・茶色の足を特徴とする鳥のぬいぐるみです。旧セーブ互換のため内部IDとテクスチャキー `fugu` は維持します。参考写真は公開ファイルに含めません。

グアムバードのPNGは画像生成で作成した独立素材です。3列×4行のマスターを `scripts/normalize-spritesheet.mjs` で補間なしに96×192へ正規化し、既存の32×48・12フレーム契約を維持します。`scripts/generate_assets.py` の旧 `fugu.png` は使用しません。

## 写真を参考にした仲間の新規PNG

シンガポール太郎は白い丸頭・黒い目・赤いマフラー・灰色の服・リュック、マーモットは丸いベージュの体・茶色い頭の毛・大きい黒い鼻・赤い口元を特徴とする生成ドット絵です。写真本体・背景・タグ・ひもは公開ファイルに含めません。

両者とも独立した3列×4行のマスターを生成し、`scripts/normalize-spritesheet.mjs` の `--fit-frames` で各コマを検出・整列し、足元を揃えた96×192に正規化しています。既存の4方向×3フレーム・32×48・倍率1・内部IDを維持し、フィールド／戦闘／クリア画面が同じPNGを参照します。旧 `marmot.png` と `vanilla.png` は保存したままロード対象から外しています。`scripts/generate_assets.py` は旧素材用のため、新PNGを上書きしません。PNG欠落時は新デザインの特徴を持つ仮画像で継続します。

## Phase 4 の戦闘・街のPNG

`public/assets/enemies/` に通常敵16種類（64×64）とキング（96×96）、`public/assets/npcs/` にNPC4人と宝箱2状態（32×48）を追加しました。パスとキーは `sceneAssets` で管理します。いずれも生成した独立素材で、欠落時はキーごとの仮画像に置き換えます。生成マスターの切り出しには `scripts/prepare-phase4-atlas.mjs` を使用します。
