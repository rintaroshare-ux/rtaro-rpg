# Ver.2 Phase 1：歩数エンカウントとATB戦闘（実装時の記録）

## 対象範囲

既存の第1章・4エリア・PNG隊列表示を維持し、戦闘だけを刷新します。既存ゲームの画像・音楽・コードは使用していません。Phase 2のショップ・売買・装備、Phase 3のタッチ操作・Android確認、Phase 4の敵15種以上や新規高品質PNGは未実装です。

## 構成

- `src/game/encounters.ts`：実移動距離、安全地帯、歩数閾値、編成抽選。Phaser非依存。
- `src/game/combat/atb.ts`：呼び出し側から渡す経過ミリ秒とすばやさでゲージを計算。DOM・タイマー・乱数・描画に依存しません。
- `src/game/combat/queue.ts`：実行順のFIFO、同じキャラクターの二重予約防止、戦闘不能時の予約解除。
- `src/game/combat/data.ts`：すばやさ、属性倍率、敵能力、ドロップ、ボスの閾値と行動パターン。
- `src/game/battle.ts`：行動可否、効果、対象再選択、AI、戦闘結果、報酬。乱数注入可能。
- `src/scenes/BattleScene.ts`：キー入力、メニュー、ATB表示、イベントの表示。演出中の処理をシリアル化します。
- `src/graphics/battleEffects.ts`：描画・Tween・Particleの演出。戦闘状態を書き換えません。
- `src/game/state.ts`：保存形式v2、v1移行、データ検証。

## 探索と遭遇

1歩は24ワールドpx。公園・駅前の草地を実際に移動すると歩数を消費します。遭遇閾値は12〜22歩、フィールド開始・加入・戦闘復帰後は先に8歩分の猶予があります。待機、壁に向かってキーを押すだけ、会話、メニュー、ワープは歩数を消費しません。

自宅・商店街の全域、横の道（y=320〜420）、左右のマップ入口、NPCの周囲74pxは安全です。画面上部と下部に安全／危険の表示があります。危険地帯を出ても残り歩数は維持し、端数距離はリセットします。マップ再読み込み・ロード時は歩数の猶予からやり直します。

敵シンボルはありません。敵数は1〜パーティー人数（最大4）から抽選し、くま・うさぎが出現します。最初の1人が4体に囲まれる状況は防ぎます。ボスは駅前の「広場のベル」に近づきZ/Enterで開始します。4人の加入が必要で、接触だけでは戦闘を始めません。

## ATBと操作

- キャラクターのすばやさ＋レベルがゲージ速度を決めます。敵も独自のゲージを持ちます。
- 満タンになると行動を予約できます。実行時にゲージを0にします。
- 初期設定はウェイト。仲間のコマンドまたは対象選択が開いている間、ゲージ時間が止まります。すでに予約された行動は実行されます。
- アクティブでは選択中も敵味方のゲージが進みます。
- 演出中は両モードともゲージ時間を止めます。タブ非表示中も停止し、復帰直後の長いデルタは抑制します。
- T：アクティブ／ウェイト切替。フィールドのメニューからも切替可能。
- 矢印/WASD：コマンド、対象、アイテムの選択。
- Z/Enter：決定。攻撃・攻撃魔法は敵選択、アイテムは種類→仲間選択の順。
- X/Escape：対象や道具の選択から戻る。
- Q/E：満タンになっている別の仲間へ切替。

## 効果と再挑戦

防御は次の行動まで被ダメージを40%にし、MPを3回復します。MP不足・道具不足・無効な蘇生対象などはゲージやアイテムを消費しません。予約後に対象が倒れた攻撃は生存している敵へ向け直し、道具は実行時にも有効性を確認します。戦闘不能者のATB・予約・防御は解除します。

- 海鮮丼：生存中の対象のHP80回復（フィールドの既存「分け合う」効果は維持）。
- 潮風ソーダ：生存中の対象のMP25回復。
- 目覚めの塩：戦闘不能者を最大HPの半分で蘇生、ATBは0から。
- もふもふヒール：生存中の全員のHPを回復。蘇生にはなりません。
- 伝説の海鮮丼：引き続き重要アイテム。戦闘の消費候補に入りません。

くまは雷が弱点・水に耐性、うさぎは水が弱点・闇に耐性です。敵を選択中に相性を表示します。ボスはHPが2/3・1/3を下回ると次の形態になり、形態は戻りません。全体攻撃・吸収攻撃のパターンとすばやさが変化します。第2形態のみ水に耐性・闇が弱点になります。

通常戦は逃走可能。すばやさ差で確率が変わり、失敗しても3回目の試行で必ず脱出できます。失敗時はゲージを消費し、ボス戦では逃走を受け付けません。

勝利時は敵全体の経験値・G・ランダムドロップを一度だけ付与します。海鮮丼は毎回1個以上入手できます。経験値は全仲間に入り、レベルアップ時にHP/MPが全回復します。逃走・敗北では報酬はありません。敗北時は自宅へ戻り全回復し、海鮮丼3個・蘇生とMP回復各1個を最低限補充します。仲間やストーリー進行は維持します。

## セーブ移行

新キーは `rintaro.chapter1.v2`、旧キーは `rintaro.chapter1.v1`。表示名・既存キャラクターIDは変更しません。

v2がなければv1を検証し、加入・レベル・HP/MP・経験値・位置・進行フラグ・海鮮丼を引き継ぎます。追加値は0G、目覚めの塩2個、潮風ソーダ3個、ウェイトです。次回保存からv2に書き込み、旧エントリは消しません。v2が壊れている場合、勝手に古いv1へ巻き戻しません。未来バージョン・不正数値・不正な加入順は読み込みを拒否し、現在のメモリ上の進行を維持します。

保存はフィールド手動保存、加入・ママとのイベント、戦闘終了、クリア時。ストレージが使えない場合は画面に通知して続行できます。戦闘の途中保存は行いません。

## 検証

```sh
npm test
npm run build
# 別ターミナルで npm run dev
npm run test:browser
npm run test:pages
```

単体テストはATB、キュー、安全地帯と歩数、複数敵、属性、予約キャンセル、蘇生、資源不足、逃走、ボス、報酬の一度限り付与、保存移行・保存失敗を対象とします。ショップの自動テストはPhase 2で実装します。

ブラウザテストでは第1章の会話・順次加入、v1のロードとv2保存、4体戦、両モード、実歩行からの遭遇と逃走、ベルでのボス開始と3形態を経たクリア、PNG欠落時の起動を確認します。テスト用に歩数抽選を固定する箇所はありますが、ボスHPの削減・報酬フラグの直接付与・ATBの満タン化は行わず、実際のキー操作で戦います。

ChromiumでのPC確認です。Android実機のタッチ・横画面はPhase 3で確認します。15〜20分の所要時間や最終的な難易度は未調整です。

ロード位置の検証はキャラクターの足元ボディが到達できるワールド端も含みます。従来の検証で拒否されていた端付近の旧セーブも、物理的に正しい範囲なら移行できます。全員が戦闘不能の状態でも戦闘が待機し続けず、敗北処理から自宅へ復帰します。

確認結果：`npm test`は27件成功、`npm run build`成功。Chromiumで第1章の順次加入→ATB戦闘→ボス3形態→切符・クリア、PNG欠落、敗北復帰、保存拒否時の継続を確認しています。`npm run test:pages`で`/rtaro-rpg/`配下の本番ファイルと画像読み込みも確認しました。Android実機、難易度・所要時間の実測、Phase 2以降は未検証／未実装です。
